# Pi 用 macOS computer use 候補（2026-09-25）

結論: **Peekaboo 4.5.0のローカル実行で、macOS標準UIの文字入力と3回のボタンクリックを実機確認した**。`--no-remote`と直近の明示的なsnapshot/要素IDを使う。Bridge経由のChrome観測にはタイトル照合の不具合があるため、Piの専用`computer_use`ツール内部でローカル実行に統一した。ブラウザ操作の通常経路は引き続き既存Playwright CLI。macOS-MCPは未導入。

| 候補 | 導入・Pi 接続 | 権限、通信、主な制約 |
| --- | --- | --- |
| **[Peekaboo](https://github.com/openclaw/Peekaboo)** | 署名・公証済み CLI を[公式 Homebrew tap](https://github.com/openclaw/Peekaboo/blob/main/docs/install.md)で提供。別経路の npm `@steipete/peekaboo` は 4.5.0、Node 22+。[MCP は stdio のみ](https://github.com/openclaw/Peekaboo/blob/main/docs/MCP.md)で、HTTP/SSE は未実装。PiではローカルCLIを包む`computer_use`拡張を導入。画像はPi標準read処理でモデル向けcontentに返す。`npx -y` の最新版を毎回取得する構成は避け、採用版・取得元・ハッシュを固定して更新を明示レビューする。 | [画面収録とアクセシビリティが必要](https://github.com/openclaw/Peekaboo/blob/main/docs/permissions.md)。Event Synthesizing は背景キーボード等で追加。GUI Bridge を使う場合は権限の付与先が Bridge ホストになる。[MCP 自体は Bridge socket やネットワーク listener を公開せず](https://github.com/openclaw/Peekaboo/blob/main/docs/MCP.md)、既定でプロセス内 stdio。[foreground 操作は既定で拒否](https://github.com/openclaw/Peekaboo/blob/main/docs/security.md)。MCP/Agent 公開ツールは `PEEKABOO_ALLOW_TOOLS` で制限可能。`see` の OCR は[Apple Vision でローカル処理](https://github.com/openclaw/Peekaboo/blob/main/docs/MCP.md)。一方 `analyze` / `agent` や分析付き `image` は[Peekaboo 側で設定した AI provider に送信](https://github.com/openclaw/Peekaboo/blob/main/docs/security.md)される。`see` が返す画像・AX テキストも Pi のモデル入力になれば、**別経路で Pi が使うモデル事業者へ渡る**。Mac 上で完全に閉じる保証ではない。 |
| **[CursorTouch/macOS-MCP 0.4.6](https://github.com/CursorTouch/MacOS-MCP)** | [Pi 拡張を同梱](https://github.com/CursorTouch/MacOS-MCP/blob/main/README.md)。拡張は[`uv run macos-mcp` を stdio 起動](https://github.com/CursorTouch/MacOS-MCP/blob/main/extensions/macos-mcp.ts)し、Pi に `mac_snapshot` など7ツールを登録。Python 3.11+、uv、[PyObjC/FastMCP 等と `uv.lock`](https://github.com/CursorTouch/MacOS-MCP/blob/main/pyproject.toml)に依存。git の移動する `main` ではなく commit を固定する必要がある。 | [画面収録とアクセシビリティが必要](https://github.com/CursorTouch/MacOS-MCP/blob/main/README.md)。MCP には任意コマンドを実行する `Shell` があり、[設定で除外可能](https://github.com/CursorTouch/MacOS-MCP/blob/main/README.md)。[HTTP/SSE も実装し Bearer 認証は任意設定](https://github.com/CursorTouch/MacOS-MCP/blob/main/README.md)なので、Pi では stdio のみとし常駐 HTTP を使わない。`Snapshot(use_vision=true)` の画像は[Pi 拡張の `resultToText` で省略](https://github.com/CursorTouch/MacOS-MCP/blob/main/extensions/macos-mcp.ts)され、モデル向け content に載らない（画像利用は未検証）。[SECURITY.md はテレメトリ無しと記す](https://github.com/CursorTouch/MacOS-MCP/blob/main/SECURITY.md)一方、[実コードは既定で PostHog SDK を生成](https://github.com/CursorTouch/MacOS-MCP/blob/main/src/macos_mcp/__main__.py)し、[米国 `us.i.posthog.com` と例外自動捕捉を設定](https://github.com/CursorTouch/MacOS-MCP/blob/main/src/macos_mcp/infrastructure/analytics.py)。`track_tool` / `track_error` の呼び出しは現行 `src/` には見つからず、通常ツール操作の外部送信は確認できない。例外自動送信と実機通信は未検証。`ANONYMIZED_TELEMETRY=false` で SDK 生成を避けられるが、文書との差があるため現状は次点。 |

**採用した接続:** `files/tools/computer-use/index.ts`をPi拡張として公開。`windows`で対象を選び、`observe`が画像・要素一覧・セッション固有の観測ハンドルを返す。`click`、`set_value`、`type`、`press`、`scroll`はそのハンドルを一度だけ消費し、Peekabooのsnapshot/窓指定の差を内部で処理する。`--no-remote`を固定し、シェル展開を介さず引数を渡す。失敗・中断後もハンドルは再利用できず、送信済みと結果確認済みをTUIとモデル向け出力で分ける。操作を自動再送しない。追加のMCPサーバーやAI provider設定は使わない。

**採用した設定:** ユーザーの導入依頼に基づき、dotfilesに公式 `openclaw/tap/peekaboo` formula、Pi専用ツールと`computer-use`スキルを宣言した。現時点のformulaは4.5.0の配布物をアーキテクチャ別SHA256で検証し、バイナリとSwiftライブラリを配置する。formula自体は上流で更新され得るため、dotfilesで4.5.0を永久固定したという意味ではない。既存のHomebrew自動更新・自動upgrade無効設定を維持する。macOS-MCPは採用しない。

**2026-09-25の実機確認:** Piの拡張読み込みエラーは0件。Playwrightはローカルページで入力・クリック・snapshot・スクリーンショット・エラー伝達を自動検証した。PeekabooはBridge/ローカルの両方でScreen Recording・Accessibility・Event SynthesizingがGrantedと応答した。

- 最初の試験では画面取得のみ成功し、Bridgeのタイトル不一致・AX要素不在・前面フォーカス検証失敗によりクリックを確認できなかった。手動クリックを成功証拠として扱っていない。
- 同じ失敗を独立Chromeプロセスで再現。WindowServerのタイトルはページ名、AXタイトルは末尾に` - Google Chrome`が付く。[4.5.0のBridge検証コード](https://github.com/openclaw/Peekaboo/blob/v4.5.0/Core/PeekabooCore/Sources/PeekabooBridge/PeekabooBridgeDesktopObservationBinding.swift#L619)はこの差を不一致として拒否する。`--no-remote`では正しいPID/窓のUI mapを取得できた。
- ローカル実行でも暗黙のlatest snapshotは既存の無効化済み状態を選んだ。直近の`data.snapshot_id`と`data.ui_elements[].id`を明示した背景クリックは、専用ページの`isTrusted: true`イベントとカウンター増加で確認できた。前面フォーカスの検証を外す設定は使っていない。
- 独立したAppKitテストアプリでも、Peekabooだけで入力欄に一意の文字列を入力し、ボタンを3回押した。アプリの実状態が同じ入力値を保持し、カウンターが`0→1→2→3`となったことを各操作後に照合し、最後の画像でも確認した。
- `success: true`でも`dispatched_unverified`の場合がある。`type`や`set-value`は送信後の照合ができないと`success: false`を返す場合もあるため、送信済み操作は自動再試行せず、受け手の状態を再観測する。背景の窓にキーボードフォーカスがないと`type`は拒否されるため、値の置換には`set-value`を使う。Riftなどで窓の位置が変わった際の`SNAPSHOT_STALE`は、新しい観測からやり直す。
- 再検証用の明示実行テスト: `node modules/pi-coding-agent/tests/computer-use-smoke.mjs`。専用Chromeを`--force-renderer-accessibility`付きで開き、Piに読み込んだ`computer_use`ツール経由でPeekabooの`set-value`と3回の`click`を実行する。Playwrightでは結果の読み取りだけを行い、一意の入力値と各回の`isTrusted: true`クリックを照合した。送信後の未検証エラーは成功と決めつけず、受け手の実状態で判定する。専用Chromeは終了時に閉じる。通常の`*.test.mjs`一括実行ではGUIを開かない。

**確認範囲:** macOS 26.5上のAppKit標準コントロールと専用Chrome。全アプリの独自描画UIや前面入力経路の動作を保証する試験ではない。画面画像をPiに読ませればPiのモデル事業者へ渡るため、依頼されたアプリ・ウィンドウの範囲に限る。両リポジトリの GitHub Security ページには[Peekaboo](https://github.com/openclaw/Peekaboo/security)・[macOS-MCP](https://github.com/CursorTouch/MacOS-MCP/security)とも公開 advisory は表示されなかったが、脆弱性がない証拠ではない。依存パッケージの全監査、配布バイナリとソースの一致、実機のネットワーク挙動は未確認。
