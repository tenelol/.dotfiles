# PRコードレビューループ

GitHub PRとその関連IssueをCodex CLIで独立レビューし、依頼範囲の指摘を修正して再確認する。通常の単発レビューではこのループを強制しない。

- レビュー対象、元の要件、修正まで依頼されているかを現在の会話とrepositoryから確定する。
- 子エージェントを使わない指定はCLIにも適用する。その場合は親が許可されたレビュー・修正を行い、独立レビュー未実施を明示する。
- 委譲する場合だけ [CLI操作・再開・結果の扱い](references/cli-workflow.md) を読む。スクリプトはスキルルートの `scripts/pr_review.py`。
- 既定のCodexレビュアーはSol / `xhigh`。Sol/Terraへの明示的なmodel指定と明示された `max` を尊重し、Lunaは拒否する。別モデルへ黙って切り替えない。
- 根拠の欠落は実際の情報源を確認して補う。取得できず結論に影響する場合だけ不足を示す。リンクを読んだという未確認の申告を検証済みとしない。
- `fix_code` / `fix_plan` は修正の許可ではない。レビューだけの依頼では報告で止める。修正まで依頼された場合は、確認済み・scope内の指摘を親が処理し、各ラウンドの再承認を求めない。
- `triage` は明示的に人間の確認を求めるproject設定がある場合に使う。既定のfirst-round/new-high承認ゲートは無効。scopeや権限を変える判断だけ確認する。
- 無関係な変更は保持し、必要なら別worktreeに分離する。push・提出・外部送信はその操作の許可がある場合だけ行う。
- 完了、停滞、上限到達を区別し、実際のレビュー回数、修正、検証と残る問題を報告する。
