# Frontend Design

Build a visual direction grounded in the subject, audience and intended action. Preserve an explicit brief and existing design system; do not invent a rejected proposal, client preference, or obligation to take an aesthetic risk.

- Choose palette, typography and layout for this content. Reuse established tokens when integrating an existing product.
- Let hierarchy and structure explain the information. Use numbering only for real sequences, and decoration only when it serves the chosen direction.
- Use motion to explain state or spatial relationships. Respect reduced motion, keyboard access and responsiveness.
- Match the design effort to the change: a complete new page may need exploration; a focused adjustment does not require multiple plans, alternative wireframes or a fixed critique ritual.
- Inspect the implemented result at relevant viewport sizes and fix observed layout or interaction problems. Do not expand successful verification into repeated aesthetic revisions without a reason.
- Use real content when available. Do not invent factual claims, metrics or customer evidence to fill a layout.

For substantial interface copy, read [writing guidance](references/interface-writing.md). Keep product labels and actions in the user's vocabulary, and leave implementation terminology out unless it helps the user decide.
