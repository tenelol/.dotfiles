# 標準メモとローカルファイルの双方向同期

memo-syncは、Macの標準メモで選択したメモを ~/Documents/memo/ に登録する自作ツール。Neovimで通常のファイルとして編集すると標準メモへ反映し、標準メモでの変更もファイルへ反映する。このMacでは全件取り込みを有効にし、新しいメモも自動でファイル化する。対応するテキスト・画像付きメモは双方向、共有や対応外の添付・書式を含むメモは標準メモからファイルへの同期にする。

## 反映と登録

denixの[memo-syncモジュール](../modules/memo-sync/default.nix)がHome Manager経由でCLI・Macのサービス・launchd agentを配置する。反映は現在のriceを確認した上でnh darwin switchを使う。

自動同期はNeovimの使用中だけ動く。フォーカス中のNeovimにmemo配下のバッファがある間、Neovimが.memo-sync/activeを1秒ごとに更新し、launchd agentを起動する。`:MemoSync`はmemoのバッファがなくてもそのNeovimの使用中は同期し、`:MemoSync!`で元に戻す。activeが30秒更新されないと、監視は処理の区切りで自ら終了する。フォーカスを外す・Neovimを終了しても30秒は続くため、直前の保存は反映される。停止中の標準メモ側の変更・新規メモ・ファイル削除は次の起動時に処理する。端末がフォーカス通知を送らない場合は、memoのバッファを開いている間は同期を続ける。

監視はローカル保存を優先し、0.35秒間変わらなかった本文を反映する。メモ側は一覧取得の完了後1秒間隔で更新日時をまとめて確認し、変わったメモを補助巡回より先に処理する。空フォルダの取り込み確認は2秒間隔。日時で検知できない変更は5分ごとの補助巡回で確認する。実際の反映時間には標準メモの読取・書込・照合時間も加わる。

| 操作 | memo/ → 標準メモ | 標準メモ → memo/ |
| --- | --- | --- |
| メモの追加・本文編集 | 対応する内容を同期 | 取り込み・更新 |
| メモの削除 | 履歴保存後に最近削除へ移動 | ローカル版を保持 |
| フォルダの追加 | 対応 | 対応 |
| フォルダの削除 | 中の登録メモを保全し、空の子から削除 | ローカル版を保持 |
| メモのフォルダ間移動 | 同じファイルの識別子で追跡 | メモIDで追跡 |
| フォルダ自体の改名・移動 | 検知して停止 | 検知して停止 |

全件取り込みは以下を実行する。「最近削除した項目」は除き、同名タイトルや既存ファイルとの衝突では別名を選ぶ。元メモの本文は変更しない。以後、新しいメモも更新日時一覧から検知して登録する。ロックなどで読めないメモは .memo-sync/import-errors.json に記録し、他のメモは続ける。

    memo-sync import-all

既に登録したメモのdisableは新規メモの探索で解除しない。import-allを明示的に再実行すると、既存登録も含めて同期の有効化を試みる。

個別に追加する場合は、標準メモで1件選び、「メモ → サービス → メモをローカル編集に追加」を実行する。対応するテキストメモは登録と同時に自動同期が有効になる。個別登録では、対応外のメモもファイルと原本は保存し、書き戻しは有効にしない。全件取り込みでは、対応外でもメモ側の本文変更をファイルへ反映する。ターミナルからも実行できる。

    memo-sync register --sync

既存ファイルと同名なら別名を選ぶ。同じメモの再登録ではローカルの編集内容を上書きしない。既存の登録は勝手に有効化されない。

    memo-sync enable "メモ名.md"
    memo-sync disable "メモ名.md"

registerを--syncなしで呼ぶと登録と原本保存のみ。初回のNotesへのAutomation許可は、対象を確認して許可する。DBの直接編集・フルディスクアクセス・apple-notes.nvimは使用しない。Automatorがシンボリックリンクを読めないため、workflowは通常ファイルとして管理する。

## ディレクトリとローカルからの新規作成

既定アカウント（このMacではiCloud）の標準Notesフォルダがmemo直下に対応する。memo/a/b/を作ると、標準メモにもa → bの階層を作る。空のディレクトリも対象。ここで.mdを保存すると、同じフォルダに新しいメモを作成して双方向同期を開始する。

    mkdir -p ~/Documents/memo/a
    nvim ~/Documents/memo/a/名前.md

同期対象は`.md`（大文字の`.MD`も可）と拡張子なしのテキストファイル。隠しファイルや画像など別の拡張子は対象にしない。新規ファイルの本文は先頭行がメモのタイトルになる。先頭行を空けて本文を書いた場合は、ファイル名をタイトル行として補い、2行目以降は保持する。Neovimでは新規メモの保存時に空のタイトル行を補う。空ファイルのまま保存していないものは待機する。自動監視は0.35秒間内容が変わらなかったファイルを作成する。既定以外のアカウントは_accounts/配下に区別して取り込み、この場所からの新規作成は行わない。

フォルダは作成・追加と、削除同期を有効にした後のローカル削除に対応する。メモのフォルダ間移動は双方向で同期する。ローカルでは同一ファイルの識別子を追い、標準メモではメモIDと所属フォルダを照合する。メモ側の移動では更新日時が変わらないため、フォルダ一覧でも所属を確認する。同じメモIDを保持して移す。

登録済みファイルを改名すると、拡張子を除いたファイル名に先頭のタイトル行を更新し、標準メモのタイトルへ反映する。1行目はファイル内に残し、2行目以降の内容は維持する。Markdownの見出し記号は維持し、ファイル名の記号は本文として正しく表示されるようエスケープする。原文同期と画像付きメモではタイトル行をプレーンテキストとして扱う。大文字・小文字だけの改名にも対応する。既存のファイル名とタイトルを一括で揃える処理は行わない。

タイトル行の変更は通常の本文同期で反映するため、共有など本文が読み取り専用のメモ、空の本文、メモ側にも未同期の変更がある場合は改名同期を停止する。移動先のファイルと元メモを保持し、理由をdirectory-errors.jsonへ残す。ファイル名を変えないフォルダ間移動では、タイトル行を変更しない。

共有メモも、同一アカウント内の非共有フォルダ同士で移動できる。メモID・本文・添付数・共有状態を移動前後で照合する。共有フォルダへの出し入れ、別アカウント、同名衝突、両側の同時移動は停止する。共有メモの本文書き戻しは引き続き無効で、移動先のローカル追記も保持する。

保存方式の違いでファイル識別子が変わった場合は自動で推測しない。元の登録と移動先が確定しているときは `memo-sync move "元の登録名.md" "移動先/名前.md"` を使う。元ファイルが存在せず、移動先が別メモに登録されていない場合だけ、そのメモIDで移動する。移動前の両側の版を保存する。処理開始前の一時的な読取・フォルダ取得失敗は再試行し、結果不明の移動はpending_moveとoperations/に残して停止する。フォルダ自体の移動・改名は別操作として未対応。

作成前にローカルの本文を履歴へ保存し、処理記録を先に残す。標準メモの作成後は本文と作成先を照合する。失敗やタイムアウト後は再作成を止め、create_interruptedとして標準メモとoperations/の記録を確認する。元のファイルは保持する。ディレクトリ・作成先のエラーは.memo-sync/directory-errors.jsonに記録する。

## 対応する内容

Markdownモードでは、見出し（#・##）、太字、斜体、箇条書き、インラインコード、コードブロックを標準メモの書式へ変換する。メモ側の編集はMarkdownへ戻す。Markdownの解析・変換にはMistune、Beautiful Soup、markdownifyをNixで同梱する。本文の文字が欠落していないことと、コード内の空白・インデントを確認して同期する。Markdownの記号や改行の書き方は、メモ側の編集を取り込んだ際に正規化されることがある。

    memo-sync markdown on
    memo-sync markdown off

onは、新規ファイルをMarkdownとして扱い、対応する既存メモのファイルもMarkdownへ変換する。更新前のファイルと原本を保存し、両側に未同期の編集があるものや対応外の書式は変換を保留する。結果は.memo-sync/markdown-skipped.jsonに残す。既にMarkdownとして登録したファイルの形式はoffでも維持し、新規・従来形式のファイルへの適用を止める。

通常のMarkdown表にも対応する。標準メモでは表が添付扱いになりplaintextにセル内容が含まれないため、HTMLの表から読み戻し、行・列・各セルと表の外の本文を照合する。先頭行を見出し行として扱う。列の左右寄せ指定や幅は標準メモの表示に従い、ローカルに書いた記法は次のメモ側編集を取り込むまで保持する。結合セル・入れ子の表・画像と表の混在は書き戻さない。

番号付きリスト、リンク、画像記法、チェックリスト、生HTML、見出し3段階目以降などを含むファイルは、Markdown原文をそのまま文字として同期する。新規ファイルと、対応するMarkdownメモへの追記が対象。画像リンクのファイルやURLは取得せず、HTMLも実行しない。書式変換できないことを理由に同期全体を止めず、記号・リンク先・コード・空白を保持する。Neovimの状態表示に「原文」が付く。この方式に切り替わったメモはそのまま維持し、`markdown on`でも再変換しない。空の本文・制御文字は拒否する。

標準メモで作成された共有・対応外の添付を含む既存メモは読み取り専用のまま。原文同期中のメモに標準メモ側で添付・表・共有を追加した場合も、文字として取り込んで欠落させず、そのメモを停止する。

### 既存画像を保持する本文編集

PNG・JPEG・GIFの画像付きメモは、画像を編集対象から外し、本文の変更範囲だけをAccessibility経由で更新する。HTML全体は置き換えず、画像の位置を表す文字を削除範囲に含めない。添付ID・参照・名前と本文を更新前後で照合する。標準メモが画像の前後に補う改行だけは区別し、その他の文字・空白の変化は拒否する。ローカルの基準版も保存するため、その自動改行だけでファイルを書き換えたり再同期したりしない。画像付きメモのファイルはプレーンテキスト扱いで、既存書式は残るが、追記したMarkdown記号からの書式変換はしない。既存ファイルに含まれる画像の代替文字（U+FFFC）は本文編集では無視する。

前面アプリを切り替えず、背景のメモ一覧から対象を選ぶ。標準メモを前面で操作中、対象が一覧に出ていない、複数の編集ウインドウがある、またはAccessibility権限がない場合は書き込まず待機し、他のメモの同期を続ける。対象ID・画面本文が一致した場合だけ編集する。途中で内容が変わった場合は自動再試行を止める。

自動同期には、実際に動かすPython実行ファイルへの「システム設定 → プライバシーとセキュリティ → アクセシビリティ」の許可が必要。ターミナルやCodexへの許可だけではlaunchdからの実行を許可したことにならない。既存の画像付き登録は `memo-sync enable "メモ名.md"` で、対応形式と競合を確認して有効化する。

## ファイル削除の同期

    memo-sync deletions on
    memo-sync deletions off

有効化後に監視されたファイルが2秒以上戻らない場合、HTML・本文とローカルの版を保存し、標準メモを「最近削除した項目」へ移す。削除済みIDの記録を残し、一覧取得で同じファイルを復活させない。永久削除は行わない。

登録済みディレクトリの削除も同じ設定で反映する。中の登録メモを先に履歴保存して最近削除へ移し、空になった子フォルダから削除する。削除の確認時間は全階層で共有し、階層ごとに待ち直さない。既定フォルダ・共有フォルダ・未登録のメモが残るフォルダは削除しない。ディレクトリの識別子で移動を判別し、フォルダ削除処理の導入前から欠落しているものには遡及しない。中断したフォルダ削除は.memo-sync/state.jsonのfolder_pendingとoperations/に残し、自動再試行しない。

有効化前から欠落しているファイルは自動削除の対象にしない。保存中の一時的な欠落、移動候補、未登録の親ディレクトリの欠落、個別に同期停止したメモ、共有メモ、対応外アカウント、メモ側の未同期変更は削除を止める。タイムアウト後も削除を繰り返さず、記録を確認して再開する。標準メモ側の削除によってローカルファイルを消す処理は行わない。

iCloudへの同期は標準メモが担当する。このツールで検証しているのはMac上の標準メモとの往復で、別端末とのiCloud往復は未検証。

## 確認と競合

Neovimではmemo配下のバッファに同期状態を表示する。`:MemoSyncStatus`で状態と停止理由、`:MemoSyncDiff`で差分を確認できる。未保存の編集がある場合はディスクとの比較、それ以外は最後の基準版に対するファイル・標準メモの比較を開く。状態は直近の同期記録を基にし、iCloudの他端末への到達を示すものではない。

標準メモから取り込むだけのファイルは読み取り専用にする。未編集のバッファには受信した更新を読み直し、未保存の編集がある場合は自動上書きしない。保存前にもディスクの変更を確認し、競合時は`:w!`でも上書きせず、バッファとディスクの両方を保持する。必要な編集をmemo外の別ファイルへ保存してから差分を確認する。この連携はNeovim起動時に読み込むため、反映後はNeovimを再起動する。

memo内のバッファは`backupcopy=yes`で保存し、保存直後の改名でも同じファイルを追跡できるようにする。memo外の設定は変更しない。開いたままのバッファも登録先の移動・改名に追従し、未保存の編集と受信したタイトル変更がぶつかる場合は両方を保持する。`:saveas`のように元ファイルを残す操作はコピーであり、ファイルの改名とは区別する。

    memo-sync status
    memo-sync diff "メモ名.md"
    memo-sync sync

statusとdiffは本文を更新しない。syncは有効化したメモを一度同期する。件数に応じて全件の読取時間もかかる。手動監視にはmemo-sync watchを使い、終了はCtrl+C。launchd agentと同じ保存先で同時に動かす必要はない。Neovimが起動する監視の確認・起動には以下を使う。

    launchctl print gui/(id -u)/org.nix-community.home.memo-sync
    launchctl kickstart gui/(id -u)/org.nix-community.home.memo-sync

監視ログは ~/Library/Logs/memo-sync.log。

上のlaunchctlコマンドはFish用。Bash/Zshでは(id -u)を$(id -u)にする。

| 状態 | 意味 |
| --- | --- |
| in_sync | 最後の同期版と両側の本文が一致 |
| push_pending / pull_pending | 片側の変更。無効な登録では保留、有効な登録では次の同期対象 |
| waiting | まだ本文を書き込んでいない一時待機。自動で再確認する |
| conflict | 両側が別々に変更。どちらも更新しない |
| converged / format_changed | 同じ本文への変更・メモ側の書式変更。同期時に基準版を更新 |
| unsupported | 内容の保持を確認できず、書き戻しを停止 |
| interrupted | 同期途中の失敗。自動再試行による書き込みを停止 |
| folder_changed / create_interrupted | フォルダ位置の変更・新規作成の中断。自動更新や再作成は停止 |
| move_interrupted | 移動途中の失敗。原本・移動先・操作記録を保全して停止 |
| unavailable | ロック・権限などで読めない。そのメモの更新は止め、他は継続 |
| deleted / delete_interrupted | 削除完了の記録・削除結果の確認待ち |
| local_missing / remote_missing | 片側が見つからない。削除設定と保護条件に従う |

競合時はmemo-sync disableでそのメモを止め、diffと履歴を確認する。必要な両側の内容を別ファイルへ保全してから、採用する本文を両側で一致させ、memo-sync enableで再開する。本文が一致しない途中失敗はenableで解除できない。force上書きコマンドは設けない。

連続保存では、書き込みが完了した版を基準に進め、新しい保存内容を次に反映する。読取失敗と書込前の待機は再試行するが、結果が不明な書込・作成・移動・削除は繰り返さない。不正なUTF-8や通常ファイルではない.mdはlocal-errors.jsonに記録して他のメモを続ける。既存ファイルがあるのにstate.jsonが失われた場合は重複作成を防ぐため監視を停止する。管理フォルダを削除して同期をリセットしない。

## 履歴と更新の保護

.memo-sync/history/に各版のHTML・本文・ID・属性、local-history/に更新前のファイル、operations/に更新記録、reports/に状態と差分を保存する。最初の原本も保持し、差分の基準は成功した同期ごとに進める。添付ファイルのバイナリ本体は保存しない。

メモへの書込直前にID・本文・HTML・日時・属性を再照合し、書込後に本文が一致することを確認する。ファイル更新にはOSの原子的な交換を使い、置き換えたファイル自体も履歴に残す。交換時に編集が入っていたら-displaced.txtへ保全し、そのメモの同期を停止する。途中処理の記録を先に保存し、クラッシュ後は一致を確認できた完了分だけ基準版を進める。

AppleのスクリプトAPIには比較と書込を一体にしたトランザクションがないため、直前の照合と書込の間の同時編集までは排他できない。両側で同じメモを同時に編集する運用は避ける。履歴は自動削除しないので容量管理は手動。管理フォルダは700、本文・原本・記録は600で作成する。

## 検証

[artifact tests](../modules/memo-sync/tests/)は合成データを使い、往復・原本保存・競合・同時保存・削除・中断・本文不一致時の停止を検証する。

| ケース | 検証する動作 |
| --- | --- |
| 通常の追加・編集・削除、空フォルダ・多階層 | 自動反映、削除猶予、原本保全、再取り込み防止 |
| メモの移動、同名衝突、移動中断 | ID保持、双方向移動、衝突先の保持、二重作成防止 |
| 見出し・強調・箇条書き・コード・表の混在 | 実機往復、本文全体・コード空白・セル配列の一致 |
| 画像付き本文、画像を取り除いた後の編集 | 実機で添付ID・前面アプリ保持、本文編集継続 |
| 連続保存、外部更新、両側編集、書込中断 | 最新版の保全、競合停止、曖昧な書込の再試行禁止 |
| Neovimの保存・強制保存・未保存バッファ | 実際のheadless Neovimで読み取り専用、差分表示、外部更新の保護 |
| 不正ファイル・パス・管理状態、ロック・共有 | 通常ファイル以外の拒否、パス外参照の拒否、欠落時停止、他メモの継続 |

これは対応範囲と代表的な障害を繰り返せる試験にしたもので、Apple標準メモの全機能や全ての同時操作を保証するものではない。PDFやスキャン・手書き・画像と表の混在、共有メモの本文書き戻し、フォルダ自体の移動・改名は対象外。共有メモの移動は共有状態・本文の不変を実機で確認した。共同編集の競合解消、iCloud別端末往復・オフライン再接続は未検証。

    python3 -m unittest discover -s modules/memo-sync/tests -p 'test_*.py'
    node modules/memo-sync/tests/test_notes_bridge.js

実機試験は明示実行のみ。以下は専用の使い捨てメモを1件作り、往復と自動監視、本文保持、古い版の書込拒否、競合時の双方保全を確認する。既存の個人メモは対象にしない。テストメモと一時workspaceは確認用に残す。

    python3 modules/memo-sync/tests/test_notes_live.py --create

画像を保持した複数段落の編集と、画像周囲の自動改行による不要な再同期を検証する実機試験は以下。専用メモだけを使い、終了時に最近削除へ移す。

    python3 modules/memo-sync/tests/test_notes_images_live.py --create

表の作成・編集・セル照合と、メモのフォルダ間移動の実機試験は以下。専用メモとフォルダだけを作り、終了時に片付ける。

    python3 modules/memo-sync/tests/test_tables_moves_live.py --create

表から原文同期への切替、HTML・画像記法を含む全文保持と双方向編集の実機試験:

    python3 modules/memo-sync/tests/test_literal_live.py --create

通常のNeovim保存から直後の改名、大小文字・日本語名、タイトル行と表・本文の保持を検証する実機試験:

    python3 modules/memo-sync/tests/test_renames_live.py --create
